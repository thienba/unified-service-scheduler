The scheduling rules (availability of a bay and a qualified technician for the whole duration, opening hours, overlap and conflict detection) live in a **pure TypeScript domain module** with no React or UI dependency. A mock API (MSW, a library that intercepts the app's network calls) calls that module and answers an OpenAPI contract, and the frontend talks only to that contract. The domain module carries the core business-logic test suite. Reason: this keeps the brief's core requirements real and testable while the backend is mocked, and lets a real backend replace the mock without UI changes.
