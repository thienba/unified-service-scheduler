**The scheduler is a booking and back-office app, not a marketing site, so it is a React single-page app built with Vite, not Next.js.** The dealership's marketing website is a separate site that links into the booking flow; SEO belongs to that site. Reasons:
- Most screens are for staff and the manager behind a role, where search engines have nothing to index; the customer booking flow is reached from the dealer's site, as the company's own Service Booking is (personalised links with the location and vehicle filled in, research.md F1.1).
- The backend is mocked in the browser with MSW (D-0000-3, D-0000-8); a Vite SPA runs MSW and IndexedDB simply, while Next.js server rendering would need a real server for the data, which is the layer we chose to mock.
- A Vite build is static files, so reviewers can open a hosted demo with no server.
If SEO ever matters (public dealership and service pages), those pages would be a separate Next.js or static site that links to `/book?dealership=…&service=…`; the booking app does not change. This settles the "suggested" framework in D-0000-5. Reason: the human's question and reading, (the human's original message is kept in the private work repo).
