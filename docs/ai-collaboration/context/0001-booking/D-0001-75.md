**Question:** "Leave without saving?" opens when the manager follows a link in the app (the tab bar, the header, the footer) or closes or reloads the tab (the browser's own question). The browser's Back button is not caught, because the app's router has no blocker for it (it uses `<Routes>`, not a data router). On a phone the tab bar is hidden while the Save bar shows, so there the question comes from the footer link or Back. Is that enough?

- A. Keep it: links and closing the tab ask; Back leaves without asking. (Built this way.)
- B. Move the shell to React Router's data router so `useBlocker` can also catch Back (a shell change, C1, that every screen shares).
- C. Catch Back with a history entry trick in this screen only.

**Decided:** catch the browser's Back button too. When the manager presses Back with unsaved changes, the same "Leave without saving?" dialog opens with Leave and Cancel; Cancel keeps them on the page with the changes. This is option B: the shell moves to React Router's data router so `useBlocker` catches links and Back in one place (a shared shell change). Closing or reloading the tab keeps the browser's own question.

Reason: the human's answer, (the human's original message is kept in the private work repo).
