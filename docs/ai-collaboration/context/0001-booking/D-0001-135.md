**Question:** React Aria's date controls take and give their dates as objects from `@internationalized/date` (Adobe, Apache-2.0, version 3.12.4). That package is installed with `react-aria-components` and is in the lockfile, but it is not in our `package.json` or in `docs/approved-dependencies.json`. `src/ui/components/DatePicker.tsx` imports `parseDate` from it to turn our `YYYY-MM-DD` text into the value the DatePicker and Calendar need. How should we hold it?

- A. List it ourselves: add `@internationalized/date` at exactly 3.12.4 to `package.json`, and to `docs/approved-dependencies.json` under D-0000-39 (React Aria's own date part, same maker, same licence). Nothing new is downloaded; the code then names every package it imports.
- B. Leave it as it is: import it through `react-aria-components`, which installs it. Nothing changes in `package.json`, but our code imports a package that `package.json` does not name, so a future update of React Aria could change its version without us seeing it.
- C. Write our own small date object for the controls instead. No import, but we would copy part of a library that React Aria already relies on, and it must match React Aria's checks exactly.

**Decided:** the recommended option. The recommendation was: A. It is the same supply-chain decision as D-0000-39, made explicit, and `check:deps` then covers it.
