**Question:** The Firefox `InvalidStateError` comes from inside MSW (3.0.3), not from our code. Should we hide it with a small workaround in our code, or keep the test allowance until MSW fixes it?

- A. Keep the allowance (`firefoxMockWorkerMessage`) as it is, and report the bug to MSW (the lead does this; the ticket gives the file, line and a minimal repro). Nothing changes in the code. The ticket's second criterion allows this when the cause is in MSW.
- B. In `src/boot-mock.ts`, before `setupWorker(...).start()`, wrap `ServiceWorkerRegistration.prototype.update` so a rejection is ignored (3 lines), and remove the allowance. This changes a browser built-in for the whole page and ignores an error on purpose (against the rule never to swallow an error), but it only touches the mock build.
- C. Patch MSW itself (for example with `patch-package`) to add `.catch()` at that line. Needs a new dependency and a patch file to keep.

**Decided:** A. The Firefox allowance in tests/e2e/whole-app.spec.ts stays. The cause is in MSW 3.0.3 (`get-worker-instance.ts` line 41 calls `existingRegistration.update()` without catching its rejection). The cause is reported to MSW as https://github.com/mswjs/msw/issues/2827 (posted 2026-10-29 with the human's OK); the allowance comment links it (PR #35). Opening the issue posts publicly under the human's account, so its text is shown to the human first.

Reason: the human's answer ("A, merge #34"), (the human's original message is kept in the private work repo).
