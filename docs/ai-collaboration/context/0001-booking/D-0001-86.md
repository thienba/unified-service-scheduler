**Question:** The approved dev panel page draws a refused request (status 400 to 499, for example the 409 "just taken") with the level "warn", an alert icon and the yellow flag badge. The API's log lines only have two levels, "info" and "error", so the mock logs a 409 as "info". How should the panel show such a line?

- A. Keep the word the API sends ("info") in the level badge, and show the status of a 400 to 499 line ("409 · 9 ms") in the yellow flag badge with the alert icon, so a refused request does not look like a normal one (what is built; no change to the API).
- B. Show the word "warn" with the flag badge for a 400 to 499 line, as the prototype does, although the opened JSON of the same line says "info".
- C. Add "warn" to the API's log levels and have the mock log 400 to 499 answers as "warn" (a change to the shared API contract and the mock, used by other tickets).

**Decided:** the recommended option. The recommendation was: A for now. The line stands out as the design wants, and the badge never says something the JSON does not. C is the cleanest match to the design if you want the word "warn" too.
