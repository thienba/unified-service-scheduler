**Found:** both live errors ("Something went wrong on our side" under Service, "We could not check the days")
have one cause, reproduced on the live site in Chromium:

1. MSW's `mockServiceWorker.js` keeps the tabs it may answer for in memory only (`activeClientIds`).
2. A browser stops an idle service worker (a tab left in the background, a laptop asleep, DevTools). When the
   next request wakes it, that list is empty, and the worker lets every request through to the network.
3. Vercel rewrites every path to `index.html`, so `/api/service-types` and `/api/.../availability` come back as
   `200 text/html`. The client cannot read them as JSON, which the page shows as "could not reach".
4. A reload sends `MOCK_ACTIVATE` again, so everything works until the worker is stopped again.

Repro: stop all service workers with the Chrome DevTools Protocol (`ServiceWorker.stopAllWorkers`), then press
Continue or pick a service: both requests return `text/html`, not from the worker, and both error cards show.

**Question:** how should we fix it?

- A. Self-heal in the client: when an `/api/` answer is not from the mock (HTML instead of JSON), start the mock
  worker again (which re-sends `MOCK_ACTIVATE`) and retry that request once. A Playwright test stops the worker
  and checks the list still loads.
- B. A only, plus `vercel.json` answers unknown `/api/*` paths with a JSON 404 instead of `index.html`, so a
  missed request fails clearly instead of looking like a network problem.
- C. Keep only the README note (D-0001-141).

**Recommended:** B. The README note then goes away, since the problem is fixed.

**Answered:** B (D-0001-142).
