**Question:** React Aria ships the words of its controls ("Previous", "Next", "Selected Date: …") in 34 languages, and the build carried all of them, although the app is English only (en-GB). The review found the main script grew by 109 kB (gzip) with the themed controls. D-0000-39 says the bundle should stay small. How should the build drop the other languages?

- A. Our own small build step, `scripts/react-aria-locales.mjs`, added to `vite.config.ts`. It keeps the English (en-US) words in React Aria's `intlStrings.mjs` files and drops the rest. No new package. A test runs it over every word list in `node_modules`, and the build stops with a message if React Aria changes the shape of those files.
- B. Adobe's own `@react-aria/optimize-locales-plugin` with `locales: ['en-GB']`. It does the same, kept up by React Aria's makers, but it is a new dev dependency: it needs your approval and an entry in `docs/approved-dependencies.json` (D-0000-17, SEC-16).
- C. Keep every language. Nothing to maintain, but about 22 kB (gzip) more on every page load.

**Decided:** the recommended option. The recommendation was: A. It needs no new package, and the test and the build check catch a change in React Aria. If you prefer the maintained plugin, B replaces it in a few lines.
