**Question:** When the manager saves opening hours (or a technician's shifts) in a way that leaves booked appointments outside them, the bookings are flagged, never deleted (Q-0001-12 A, AD-14). The brief for this design asks for "a clear warning first". `PUT /dealerships/{id}/settings` and `PUT /technicians/{id}/shifts` only report the flagged bookings *after* they have saved. How does the screen warn before saving?

**Decided:** the recommended option. The recommendation was: A. It is the only option that warns with real numbers before anything changes, and the cost is one query parameter that runs the same flag test without writing (AD-14 already has that test as a pure function). The design (manager-dealership-settings.html and manager-shifts.html, states `checking`, `confirm-flags`, `saved-with-flags`) is drawn with A. If B is chosen, the `checking` and `confirm-flags` states go, the fixed info line stays, and `saved-with-flags` stays as it is.
