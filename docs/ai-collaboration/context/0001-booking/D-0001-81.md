**Question:** Small choices in the outbox screen where the design and the ticket leave a gap. Each is easy to change.

- 1. Groups are listed newest activity first (the newest confirmation, move or cancellation), as the prototype draws them; inside a group, in the order made.
- 2. The appointment's id is left out of the banner ("Showing the messages for Full service, Marta, Mon 2 Nov, 09:00.") and of About ("Full service on Mon 2 Nov, 09:00"): real ids are long random strings, not "AP-1042".
- 3. The first name is the first word of the customer's name; with no name it reads "the customer".
- 4. The empty and filter-empty states use the shared StateBlock "empty" icon (plus), not the prototype's mail icon (StateBlock has no icon option).
- 5. filter-empty words for the other two filters follow the Cancelled pattern: "No scheduled messages" / "A message is scheduled while its time is still ahead. None are scheduled at the moment." and "No messages sent in this demo" / "A message counts as sent in this demo once its time has passed. None have reached their time yet."
- 6. A row on desktop has `aria-pressed`; below 1024 it has `aria-haspopup="dialog"` instead (it opens a sheet, it is not a toggle).
- 7. The another-dealership words are the shell's (C1): "… has its own manager." without "and its own outbox".
- 8. Transport sentences in the confirmation: "You are waiting on site.", "You are dropping the car off.", "A courtesy car is ready for you."
- 9. A link the API sends that is not on the page's own origin is shown as nothing (left out), not as text.
- 10. The XSS test uses a first name with no spaces (`<img/src=x/onerror=window.__xss=1>`), because the first name is the first word. (Since the review it also runs with the ticket's exact name, whose first name is `<img`.)
- 11. (Added after the review.) The screen reads each appointment in the outbox to name it. If one of those reads fails, the whole screen shows "We could not load the outbox." with Try again, even though the other messages loaded. The other way is to show the messages that loaded and an Alert such as "Some messages could not be shown. Try again." (new words, not in the design). Kept as built until you say.

**Decided:** the recommended option. The recommendation was: keep all eleven. For 11, keep the whole-screen error: it is the designed state, and a part-loaded outbox could hide that a customer's messages are missing.

Reason: the human's answer ("còn lại theo đề xuất", take the recommendation for the rest), (the human's original message is kept in the private work repo).
