**Question:** "Move" on the flagged list opens `adjust` "with the closest times that fit already listed" (manager.md 4.2), and `adjust` shows "Times that fit" for any flagged booking. The contract has no call that finds free times for an appointment while leaving that appointment out. The only read is `POST /availability-checks` at the booking's own start, and it counts the booking's own technician, bay and car as busy during its own time. So a time that overlaps the booking itself, and is free only with its own technician or bay, is missing from the list. (The PATCH answer after a refused move does leave the appointment out, so the clash list is exact.) What should "Times that fit" come from?

- A. Keep `POST /availability-checks` at the booking's start, as built. Most times are right; a few that overlap the booking itself may be missing. The booking's own start is left out of the list, since choosing it changes nothing.
- B. Add an optional `excludeAppointmentId` to `AvailabilityCheckRequest`, for staff and managers of the dealership only (the domain check already has this option for the manager's move). The screen sends it and the list is exact. A small contract, mock and application change in its own ticket.
- C. Add a read `GET /appointments/{appointmentId}/suggestions` for the manager. Exact, but a new route.

**Decided:** B, the same field as D-0001-101: `POST /availability-checks` takes the optional appointment id (one name for both calls, `appointmentId`), for staff and managers of the dealership; the `adjust` screen sends it, so "Times that fit" is exact and matches what Save accepts.
