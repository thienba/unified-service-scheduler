**Question:** What does the dev panel show after "Reset demo data" succeeds? The prototype's `reset-done` state (manager-dev-panel.html) draws the toast "Demo data reset. The starting data is loaded again." over an empty page ("No requests yet" / "The demo data was reset. Use the app, then come back…"). The ticket says the numbers and lines "stay as the tab's own" and quotes "Demo data is back to the start". The API agrees with the ticket: `POST /_demo/reset` resets the stored data only; the logs and metrics are in the tab's memory and stay (the reset itself adds lines).

- A. Keep the tab's numbers and lines on screen, show the prototype's toast, and add one quiet line in the "Reset demo data" section: "Demo data is back to the start." (what is built).
- B. As the prototype: after a reset show the "No requests yet" block although lines exist (the page would hide lines the API still returns).
- C. Clear the logs and metrics too on reset (a change to the mock and the contract description; "Reset" would also wipe what you were tracing).

**Decided:** the recommended option. The recommendation was: A. The page tells the truth about what the API holds, the toast keeps the approved words, and the line keeps the ticket's words after the toast has gone.
