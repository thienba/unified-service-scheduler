**Question:** When the same confirm is sent twice (same key, same body), the second answer must be "the same". The saved record holds ids only (SEC-8.AC-5), so the command answers with the appointment as it is stored now, not as it was at the first answer. If the appointment was rescheduled or cancelled in between, a late retry shows the newer state. Is that right?

**Decided:** the recommended option. The recommendation was: A. A retry after a double-click or a bad network happens within seconds, when both are the same. For a retry hours later, the current state is the more useful answer. B is a small change in `idempotency.ts` if exact replay is wanted.
