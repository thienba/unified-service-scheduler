**Question:** Small choices in the app shell where the design and the ticket leave a gap. Each is easy to change.

- 1. The "Who" select (D-0001-62 A) shows when the current role has more than one demo user, and picking a role chooses the first user of that role in the API's list order. Staff therefore starts as the first staff user, not London.
- 2. The form-summary Alert does not take focus (the first invalid field does, as the ticket says); design.md 8.16 says summary alerts take focus on their heading. The two cannot both hold.
- 3. Dealership "city" is not in the contract, so the picker shows the name only. The note "Times are in London time." takes the place from the zone name (`Europe/London` gives London).
- 4. On a page that is already an error or no-permission, the title takes focus only after the person has used the page, so a fresh load keeps the skip link as the first Tab stop.
- 5. Until a screen's own ticket adds it, a route the role may open shows its title and "This screen comes in a later step." (so the role homes, the tabs and the guard can be shown).
- 6. Reads are not retried either (not only writes): an error shows at once with Try again.
- 7. The other-dealership state for staff is decided in the browser from `me.dealershipIds` (there is no API call that answers 403 for a dealership id alone; `GET /dealerships/{id}` is open to every role). A 403 from a screen's own call shows the generic no-permission words.

**Decided:** the recommended option. The recommendation was: keep all seven.
