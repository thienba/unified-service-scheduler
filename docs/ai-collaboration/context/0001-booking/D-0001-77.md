**Question:** The ticket says each message's cancel link is the app's origin plus `/appointments/<id>/cancel`. The built `GET /outbox` sends `cancel: <origin>/appointments/<id>` (the appointment page, where the customer presses Cancel); `/appointments/<id>/cancel` exists only as the API's POST, not as a screen, so a link to it would open "We cannot find that page." The screen shows the links the API sends. Which cancel link should a message carry?

- A. Keep the API's link: `/appointments/<id>` (the appointment page with its Cancel button). Change the ticket's wording.
- B. Add a screen route `/appointments/<id>/cancel` that opens the appointment with the cancel dialog open, and change the API's link to it (a backend and a routes change in another ticket).

**Decided:** the recommended option. The recommendation was: A. It works today, holds no other data (SEC-17.AC-2 holds), and needs no new route. The outbox test checks that every link is the app's own origin and one of `/appointments/<id>` or `/appointments/<id>/reschedule`.
