**Question:** What should the manager see for an appointment that has already ended? Q-0001-242 item 10 hides Adjust on the appointment page for a past booking, but the schedule's detail panel still offered Adjust or Move for it, and the `adjust` screen opened its form for a finished job. The API itself does not refuse such a change (it only checks the new time), and the design has no state for it.

- A. Hide Adjust and Move for an appointment whose end has passed, on the schedule's detail panel as on the appointment page. If the manager still reaches `adjust` by its address, show an info Alert instead of the form: "This appointment has ended", "It was {day and time} with {technician}. A finished appointment cannot be moved or changed.", with Back to schedule. Nothing is sent.
- B. Hide the buttons, but keep the form on `adjust` for a finished job (a manager may want to record that it really happened at another time).
- C. Show the buttons and the form for every appointment that is not cancelled; the garage decides.

**Decided:** the recommended option. The recommendation was: A. It keeps one rule on every screen (a finished job cannot be moved, as Q-0001-242 item 10 already reads on the appointment page), and moving a job that is done would send the customer a message about a visit that has passed. Built as A; the API rule (refusing a change to a past appointment) would be its own backend ticket.

Reason: the human's answer ("Còn lại theo đề xuất", take the recommendation for the rest), (the human's original message is kept in the private work repo).
